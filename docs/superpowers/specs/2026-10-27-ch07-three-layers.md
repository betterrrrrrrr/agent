# 第七章升级方案

用户要求：阅读 7.2 和第七章知识文档，用 Superpowers 模式完成三层上下文和动态预算。升级目标经确认是 daima。

## 设计

- 保留 MySQL、LangGraph checkpoint、add_messages 和 LangChain trim_messages。
- summary_upto_msg_id 是已摘要闭区间上界，layer1_from_msg_id 是原文层之前的闭区间上界；中间部分按规则渲染，原始 State 不改写。
- 每轮结束从 checkpoint 完整消息计算层 1 边界及层 2 的实际压缩 token 数（包含工具）。边界只前进，至少保留最近一轮。
- 层 2 超预算才启动后台摘要。摘要仅覆盖已降级区间，旧摘要只供消歧背景；新段和投影、摘要边界同事务提交。锁定会话并校验预期旧边界，丢弃过期任务。
- 预算由窗口减系统/工具定义、证据、摘要、输出、安全余量以及本轮 ReAct 峰值得出，再与目标轮数预算取小。中文 token 估算统一用字符/token 除数。未知模型采用保守窗口并报警，允许显式覆盖。
- 工具调用对保留 tool_calls/tool_call_id；本轮消息整体保留，不在工具调用与返回之间切窗。
- 模型请求仅一条固定 system；摘要和证据插在最后一条真实用户消息之后。
- 超长用户输入在进入图和落库前拒绝，API 输出和工具结果设上限。预算不足可启动报警，模型调用前拒绝超限请求。

## 验收

预算公式、配置校验、三层渲染、工具关联、原文不变、层级推进、按用量触发、空摘要/失败回滚、并发防抖/过期写入、分段投影、跨轮加载/续跑及固定 system 缓存回归。
本地 SQLite 仅用于隔离测试；生产方案仍是 MySQL。真实模型摘要质量单独以标注样例脚本验证，无账号时不冒充实测。

Superpowers 技能和 Context7 MCP 在当前环境不可用。按其方案→计划→测试→实现→评审→验证顺序执行；库接口以项目已安装版本签名和源码核对。文档 7.2 后半段保留了双层旧计划，本次以 7.1/7.3 及 7.2 开头三层需求为准。
